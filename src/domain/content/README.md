# Content input boundary

Concepts, Primitives, Speaking Guides and Skill Maps use shared input boundaries in Astro, CLI validation and their generated portable schemas. Speaking Cards remain the concrete stored format for speaking guides.

`conceptInputSchema`, `primitiveInputSchema`, and `speakingCardInputSchema` remain separate contracts. Speaking Cards are the current stored format for speaking guides, a kind of application resource. Skill Maps have independent Map/Node/Journey/Relation contracts; no common opaque resource payload replaces the existing contracts.

Concept and Primitive input `added` values must be real ISO calendar date strings (`YYYY-MM-DD`). Input contracts produce strings. Their Astro adapters convert validated dates to UTC `Date` values for existing pages and exports. The shared `yamlContentLoader` retains glob discovery and watching while using the CLI's YAML parser, so quoted and unquoted dates follow the same input rules. Each load reparses its collection because glob's YAML digest does not track extracted contract changes. Speaking Cards use the same scoped loader and revalidation behavior.

Concept `sources`, `aliases`, `examples` and `distinguish_from` default to `[]`. Examples are strict `{ context, example }` objects with nonblank prose. Distinctions are strict `{ target, distinction }` objects with slug syntax and nonblank prose. The public catalog rejects missing/self/repeated targets even when repeated targets have different prose; portable JSON Schema verifies field shapes without proving these cross-record semantic rules. Aliases are trimmed and nonblank, unique ignoring case, and different from the same record’s term/zh ignoring case. Portable JSON Schema enforces the expressible string/array shape and exact uniqueness. Normalized uniqueness and comparisons to sibling fields are semantic input checks shared by Node, CLI and Astro; a raw JSON Schema validator alone does not establish these rules. Use the complete catalog boundary before publication. Unknown fields, duplicate relationship references and invalid filename slugs are rejected. Text limits count Unicode code points; source URIs use the same standard URI validator as portable-schema tests. These choices close actual differences between JavaScript string/URL behavior and JSON Schema acceptance without changing existing canonical values.

Primitive text is trimmed and must contain non-whitespace characters. Definitions, considerations and sources are nonempty. Nested objects remain strict, and `related` references are unique. HTTP(S) source URLs use the shared standard URI validator plus a host-and-scheme pattern carried into JSON Schema. Source hosts are names, explicit four-octet decimal IPv4 addresses or bracketed IPv6 addresses; supplied ports are limited to 0–65535. This avoids browser URL coercion and invalid numeric hosts. The same portable pattern enforces these rules; ownership, priority and source vocabularies remain unchanged. Referenced definitions retain only their Concept slug and are resolved from canonical Concepts at build time.

`npm run schema:concept` and `npm run schema:primitive` generate their portable schemas from the input contract using `io: 'input'`. This keeps omitted defaults optional. The generator retains Zod's default rejection of unrepresentable types, and tests exercise the written schema with [Ajv's format validation](https://ajv.js.org/guide/formats.html). `npm run schema:speaking-card` generates the Speaking Guide contract. All committed schemas are derived from input rules. `npm run schema:generate` regenerates them together. `npm run schema:check` compares exact deterministic bytes without changing files; it is part of `npm run check` and CI. A failure names every missing or drifting schema.

`readConceptInputs(directory)`, `readPrimitiveInputs(directory)`, and `readSpeakingCardInputs(directory)` accept a filesystem path or file URL. Without an argument they use the corresponding canonical directory. They return `{ files, records, errors }`:

- `files` lists direct `.yaml`/`.yml` filenames in lexical order.
- Each valid record contains `{ slug, file, data }`; the filename stem remains its slug. Speaking Card records sort by their unique `data.number`, preserving gaps and existing anchors.
- `errors` contains file and field diagnostics. Nested YAML is reported but never parsed as a direct record. Non-YAML files are ignored.

Consumers must reject a directory result with any errors before publishing or applying its records. Valid records remain in the result to support diagnosis; this is not approval of a partial catalog. Filesystem failures to enumerate a directory propagate to the caller. `validateConceptDirectory` uses the shared reader, then validates concept targets, self-links and duplicate terms. `validatePrimitiveDirectory` uses the shared Primitive reader, then checks primitive targets, self-links, duplicate terms, repeated defining-concept references and required defining-concept backlinks.

Speaking Guide numbers are positive safe integers. Nonblank speaking notes and unique references are field rules; empty relations remain valid. The shared reader rejects duplicate numbers, malformed YAML and nested records, retaining numeric order and public anchors. `readSpeakingCards` adapts its diagnostics to the script API without maintaining separate file discovery rules.

## Complete catalog boundary

`readCatalog(directory?)` and `validateCatalog(catalog)` are public exports from `catalog.mjs` and run directly in Node without Astro. The optional directory is a path or file URL for a data root containing `concepts/`, `primitives/` and `speaking-cards/`; omitted means the canonical root. Reading validates input fields and returns `{ concepts, primitives, speakingCards, errors }`. Each collection contains the reader's `{ slug, file, data }` records; dates remain strings. File errors include their collection path. Enumeration failures propagate.

Pass that read result to `validateCatalog`. It returns `{ errors, categoryCounts }`, retaining input diagnostics and adding missing targets, self-links, duplicate terms and required definition backlinks. Reject any errors before publication; retained records are diagnostic and do not authorize partial publication. The function validates the relationships of already parsed records; arbitrary raw objects must enter through the input readers/contracts first.

`npm run validate:catalog` uses this boundary. Existing `validate:concepts` and `validate:speaking-cards` commands alias it, so callers receive complete validation. `validateConceptDirectory` and `validatePrimitiveDirectory` remain scoped Node entry points for individual collections, using the same reference rules. Migration-only script validators, raw reader and three separate schema generators have been removed. Astro Date adapters remain because existing projections require their output.

Category names and metadata are loaded from `src/data/taxonomy/categories/` by `src/domain/taxonomy/categories.mjs`. One validated registry drives the Concept enum, CLI, generated schema, routes and ordered grids; empty configured categories are valid. Primitive layer names and explicit public anchors come from `src/data/taxonomy/layers/` through `src/domain/taxonomy/layers.mjs`; configured empty layers are valid.

Category YAML requires all six metadata fields and rejects unknown fields, duplicate names/slugs/orders, invalid slugs and nested YAML. The reader accepts a path or file URL and returns `{ categories, errors }`, sorted by `order`; consumers reject all errors. The canonical registry fails fast on invalid configuration. Native Node resolves the canonical directory relative to the module. Astro config pins the taxonomy directory during prerendering because bundled module URLs move into `dist`; this path is build input, not a public content identifier.

Category and layer readers reuse one direct-YAML discovery/diagnostic helper. Layer records require `name`, a kebab-case `layer-*` anchor and positive integer `order`; names/anchors/orders are unique. `layerAnchor(name)` resolves the stored public anchor and fails on unknown names. Layer validation reserves both section anchors and generated heading IDs, preventing collisions within the navigation namespace. Cross-record validation also rejects a Primitive filename slug that collides with either target. The page and validators use the same heading-ID rule.

## Skill Maps

`readSkillMaps(directory?)` reads fixed map directories, diagnoses invalid identity/files/shape, injects path-derived IDs and validates internal node/taxonomy/source/journey references. It returns `{records,errors}` and is shared by the Astro skillMaps loader and CLI catalog. Missing skill-maps directories are allowed for existing catalog callers. Existing content types retain direct-file discovery.

`skill-map-input.mjs` owns four input shapes and the assembled collection shape. Portable schemas are generated by content-schemas.mjs. `validateSkillMapSources(records)` enforces the public source baseline; pending sources remain valid for input fixtures. `validateSkillMapSnapshotChanges(previous,current)` detects commits/repositories/roots repointed under the same snapshot ID during update review. This is a comparison seam, not a claim that parsing one version proves immutable history.

Relationship tables may contain cycles; guidance repeats nodes across steps without inventing dependency edges. Different maps own independent namespaces and taxonomy. Nodes/paths can retire while their detail routes, stored relationships and source snapshots remain available. Future knowledge_refs are documented in the approved design but are rejected as unknown input fields in this version.

## Translation assets and localized projections

Translation overlays use the strict `translationInputSchema` and generated `schemas/translation.schema.json`, independently of Concept/Primitive input contracts. Auto-discovered YAML assets below `src/data/translations/` have stable `(locale, kind, target_id)` identities; the initial locale is `zh-CN`. `readTranslations(directory)` returns `{ records, errors }`, with records `{ id, file, data }`. Missing directories mean empty only for `ENOENT`; invalid YAML, duplicate identities and schema violations remain diagnostics. All diagnostics must be rejected before publication.

The public `readCatalog` result now also includes `translations`, `categories` and `layers`. Supplied taxonomy is read from the caller's own `dataRoot/taxonomy/`; legacy roots without taxonomy retain canonical registry compatibility. `validateCatalog` adds translation target/path/shape checks. `translationsLoader(dataRoot)` uses this same complete boundary for Astro rather than a second parser or Zod-only target validator.

`translationUnits(kind, target_id, canonicalData)` exposes registered source descriptors and deterministic `sourceFingerprint` values. `resolveCatalog(canonicalCatalog, overlays, locale)` returns immutable display records with unit languages, reviewed/missing/draft/stale state, coverage and core translation eligibility. Primitive referenced definitions reuse resolved Concept units; canonical reference branches remain intact. Exports continue reading canonical collections. See [the overlay contract](../../../docs/design/translation-overlay.md) for the complete path registry, whole-owner vector freshness, review-date requirement, fallback and publication policies.
