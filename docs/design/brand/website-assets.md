## 提取与质量边界

1. **定位与记录**：为每项素材记录原稿、章节、源文件摘要、裁切范围和制作方式。完成条件：10 项都有可定位来源，原图保持字节一致。
2. **分离图形**：从原稿中分离目标，去除版面标签与纸底，保留形态；字标、符号与图标的矢量路径对照透明参考图验证。完成条件：素材不携带说明文字、分隔线或背景矩形，SVG 自包含且缩放不变形。
3. **保留人物**：主视觉提取以原姿态为基线，检查弓弦、箭、头发、披风与坐骑轮廓。完成条件：没有新增人物、改姿态或把缺失细节的重绘冒称原图提取。
4. **适配媒介**：图标/字标准备主题变体，主视觉准备符合源像素能力的显示尺寸，生成实际尺寸预览。完成条件：16/32/64 px 符号、24 px 图标、120 px 起字标和主视觉样张均能查看并通过比对。
5. **交付索引**：记录格式、像素尺寸/viewBox、主题、来源及实际用途，给出独立可打开的预览。完成条件：开发票可根据稳定素材身份消费同一份交付，不重新选择形状或维护第二份母版。

栅格素材的有效尺寸按源图目标区域的实际像素确定。导出大尺寸、放大或增加像素数量本身不能证明细节足够。若主视觉质量无法支持拟定显示尺寸，记录该项限制并调整显示尺寸或修复交付；不能以整页规范板、占位图或新姿态角色替代。

## 拆票方案

所有票据关联 Spec #44；T01/T02 分别对应已发布的 #45/#46。按用户的 MINIMUM-TICKET INVARIANT，将整个升级作为候选，仅保留用户明确要求的素材前置交付边界。原页面开发票 2–8 合并为一票，内部实施步骤和检查点不再分别建票。

| 草案 | 标题 | Blocked by | 完整交付 | Spec 验收 |
| --- | --- | --- | --- | --- |
| T01 | 网站素材包与实际尺寸预览 | 无 | 10 项基础素材、必要变体、来源索引、可打开的预览及原稿归档 | AC-P0-04 素材部分、AC-P0-01 尺寸样张部分 |
| T02 | 网站品牌视觉升级与内容传播 | T01 | Header/favicon、首页/任务入口、默认 OG、目录/详情/六类搜索身份、Speaking Guide 双画幅下载与静态分享页、Task Journey/Skill Map 语义阅读增强 | 全部 AC-P0、AC-P1 与公共验收；素材检查复用 T01 证据 |

### 硬约束与合并检查

- **上下文容量**：现有首页、共享行/标题组件、语言与元数据入口、地图投影及测试边界已经定位。新增内容仅为静态分享投影与构建图片生成；规范数据、schema、公共身份和主题模型不变。目前没有可靠证据表明某个开发子范围必须跨独立上下文，因此不以功能数量或潜在并行为由拆票。
- **独立验证**：T01 用实际素材与预览验收；T02 用完整生产构建、真实页面行为、元数据/图片响应及 fixture 验收。合并不会取消任何 Spec 验收项，也不依赖未来票才能证明完成。
- **仓库有效性与顺序**：不涉及 schema 迁移、expand-contract 或必须隔离的 prefactor。默认 OG → 单卡 OG、共享图标 → 页面消费等顺序在 T02 内完成并逐步检查，内部步骤不需要变成 blocking Issue。
- **保留的边界**：T01 → T02 来自用户明确要求的“先素材提取、再页面开发”。只有素材形态、尺寸、主题与来源已验证，T02 才消费交付；不把不确定素材处理和页面实现混在同一完成判断中。
- **合并结果**：原开发票的相邻及依赖关联范围均可合并。T01 按本次要求单独保留，最终为两票。如实施中出现上述硬约束的具体证据，再说明违反项并调整；不预先为假设性超限拆票。

执行顺序：T01 → T02。T02 内部保留 P0 品牌入口/首页/默认 OG → P1 身份/分享/地图的检查点，支持分步验证和审查；整个票据完成仍要求全部适用验收。检查点、实现步骤或多次本地提交均不是新增票据的理由。
