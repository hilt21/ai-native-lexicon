# 首页主视觉优化方案 A

状态：首轮最小设计实验已本地接入，正在完成页面验收；尚未发布。2026-10-09；源码基线 `e5f3cda`。素材及预览见 [v2 交付](hero-artwork/v2/README.md)。本轮包含尺度/位置、Dark 体块和北极星箭尖三个变量；P2 辅助图形和 P3 新微交互不加入本轮。

依据：[改进品牌形象呈现访谈](chatgpt-conversation://6ac8d43f-6268-83e8-8893-e706dcc07185)、用户提供的 [Dark 截图](references/2026-10-09-home-dark.png) / [Light 截图](references/2026-10-09-home-light.png)、[品牌规范](visual-language.md)、[素材交付边界](asset-delivery.md) 和 [现有设计系统](../redesign-system.md)。访谈为设计建议；尺寸估计、示意 SVG 和代码占位引用不能替代真实素材与浏览器测量。

## 设计判断与范围

这是面向技术读者的编辑式知识网站，采用 **Redesign - Preserve**：让完整的少年骑独角兽满弓形象成为更有分量的编辑式主视觉，与左侧文字形成联系。继续使用 Astro / Starlight、原生 CSS 和现有语义 token。

| 设计参数 | 取值 | 理由 |
| --- | --- | --- |
| `DESIGN_VARIANCE` | 6 | 延续非对称双栏，重组右栏的尺度与留白 |
| `MOTION_INTENSITY` | 4 | 保留现有一次性 CSS 入场及 reduced-motion；主视觉构图保持静态，不新增动效 |
| `VISUAL_DENSITY` | 3 | 留白承托完整角色，文字与主要入口优先 |

字体继续使用现有 Georgia 展示标题及系统正文/等宽栈。酸绿 `#C8FF3D`、墨黑、纸色和全页主题规则延续品牌依据。字标、标题、价值说明、主次操作、导航、四任务区和后续内容保持当前职责；本轮只改首页主视觉及其布局。

## 当前问题与可检查事实

| 项目 | 当前实现 / 截图表现 | 对方案的影响 |
| --- | --- | --- |
| 尺度 | `.brand-mascot` 桌面宽 245 CSS px、窄屏宽 180 px | 访谈的约 290/300 px 是截图估计；30%-40% 的首轮增幅应换算为约 320-340 CSS px |
| 位置 | 固定 245 px 右栏，图片垂直居中；左侧标题较重 | 放大时同步分配右栏与间距，避免只用 `transform: scale()` 覆盖文字或越界 |
| Dark 图形 | 两主题共用同一透明图；黑色披风/服装与深色背景融合 | 单纯增大仍会留下空心线稿感，需要独立 Dark 资产 |
| 品牌联系 | 箭尖只有极小的绿色痕迹 | 使用已有北极星形成可见但克制的绿色锚点 |
| 清晰度 | 母版有效尺寸 491 × 626；当前 245 px 上限来自 2× 约束 | 原图放大到 340 px 只有约 1.44×，必须明确新的素材质量门槛 |
| 页面契约 | 原生主题/语言/搜索；既有 locale/base、OG 和稳定链接 | 主视觉封装独立，不改这些入口、状态与索引政策 |

上传截图包含设备像素和可能的缩放因素，不能直接把截图里的像素宽度当 CSS 宽度。后续以浏览器 viewport、DPR、元素边界和非透明轮廓共同校准。

## 首轮方案：三个变量一起完成

### 尺度与构图

以 **1440 × 900** 为主要桌面参照，图像宽度起点为 **330 CSS px**，在 **320-340 px** 内校准。保持原比例，340 px 对应约 434 px 高；保留人物、弓、箭、坐骑与披风的完整边界。

右侧采用“图像宽度 + 约 24-40 px 右侧留白”的布局槽，让视觉中心相对当前结果左移约 60-100 CSS px。扩大图像本身已经会移动左边界，额外位置调整以测量结果为准，避免叠加两次过大的左移。垂直方向先测试向上约 16-24 px，再按弓顶、面部与双行标题的关系校准。

文字与角色之间保留约 32-48 px 的有效间隔，箭尖朝向标题邻近的留白。人物面部与标题上半部形成呼应；不通过翻转、旋转角色或改变持弓姿态来强行对齐某个字。图像不遮挡标题、说明、按钮，也不越过首页内容容器。

| 视口宽度 | 布局 | 图像宽度实验范围 |
| --- | --- | --- |
| 1440 px 及以上 | 完整双栏，保持上述视觉重心 | 320-340 px，首选 330 px |
| 1200-1439 px | 双栏，压缩右侧留白与栏间距 | 300-320 px |
| 800-1199 px | 紧凑双栏，图片不作额外左移 | 245-280 px，避免挤窄标题 |
| 320-799 px | 单栏，沿用项目 50rem 边界；文字与 CTA 后展示完整角色 | 220-240 px，随实际可用宽度收缩 |

这些是实验起点，最终值取决于真实轮廓、文本换行与首屏几何；小高度桌面优先收缩图像和垂直留白。移动端不要求图片和 CTA 同时完整进入首屏，要求价值说明和主 CTA 优先完整可见。保留现有原生主题/语言控件。

### 独立的 Light / Dark 素材

Light 保持墨黑主体和纸色负空间；Dark 制作暖白实体与深色负空间的独立版本，让披风、衣装和坐骑恢复体块。两版须保持相同姿态、轮廓、面部身份、画幅和锚点。

采用逐区校准的双色表现，人工核对脸、眼睛、发型、弓弦、手指、独角兽眼鼻、披风与马蹄。全图 CSS `invert()` 不能作为交付版本：它可能把脸部变成负片，也无法保证两主题的视觉重量接近。整幅纸色底板同样不作为首选，它会引入与 Dark 页面割裂的亮色区域。

**素材交付方式已落实：**按用户指令使用内置生图工具，以既有角色和品牌图版制作高分辨率 Light/Dark 母稿，再双色描摹为不嵌入位图的真实 SVG 路径。v2 提供共同 1111 × 1416 viewBox、固定箭尖锚点及 680 × 867 WebP，支持目标 340 CSS px 的 DPR 2 展示；尺寸、形态和浏览器解码已核对。

无需等待外部高清素材即可继续接入。v1 原图的 245 px 限制只适用于旧的原像素交付，不能机械套用到新路径稿；v2 明确标为生成式重制，记录母稿、提示词、来源、描摹参数、文件摘要及局部对照，不宣称是原始设计矢量文件。既有原稿和提取稿保留，网站按独立版本消费新素材。

### 北极星箭尖

复用现有 `north-star.svg`，不用通用图标库替代品牌形状。箭尖附近增加约 **16-20 CSS px** 的北极星锚点；以实际轮廓检查大小，不放大成第二个 Logo。

保持 0° 方向、原形状比例和内部白色镂空，酸绿与 `--lex-acid` 相同。锚点位置相对图像固有坐标定义，并随图像整体缩放；不相对 viewport 写死偏移。最终制作时定位真实箭尖，避开脸、手和弓弦，处理原图残留的小块异色绿色。

主体保持黑白，仅箭尖使用绿色。不开光晕、粒子、箭轨虚线或持续闪烁；图形为装饰语义，不形成可点击热点。

## 辅助图形与动画的取舍

完整访谈最后建议首轮只做上述三个变量，因此这次不把背景装饰混入最小实验。

- **编辑式辅助线：**作为后续可选试验，只在确实承托角色构图时尝试一个低对比角弧或短基线，沿用品牌辅助图形。移除它后构图仍应成立；不铺装饰网格或十字准星。
- **`FIG. 01 / FOLLOW THE NORTH STAR`：**不采用。它增加图片上的编号/装饰文案，与本次保留干净主视觉的目标和 taste skill 的标签约束不符。
- **视差、漂浮、3D 与新动画库：**不纳入本轮。既有入场效果继续遵守 reduced-motion；不因使用设计技能而提高动效强度。

## Astro 实施边界与顺序

按一条完整实施任务推进，以下为内部检查点，不按文件或层另拆票：

1. **准备素材与实际尺寸对照。**交付同一轮廓的 Light/Dark 候选、箭尖锚点和来源记录；在拟定宽度与 DPR 1/2 下核对清晰度、体块和角色身份。
2. **接入 `HeroArtwork.astro`。**从 `HomePage.astro` 提取仅主视觉部分，管理明暗素材、固定比例、锚点与响应式尺寸。使用 Starlight 已有 `[data-theme]` 状态支持 Light/Dark/Auto 和系统主题变化，不建立第二套主题状态。
3. **调整首页 Grid 与局部 CSS。**复用 token 和原生 CSS；不迁移 React/Tailwind，不引入动画或状态依赖。本轮装饰图采用 `aspect-ratio` 预留空间，以 CSS `image-set` 选择 1×/2× WebP，并随现有 `[data-theme]` 选择 Light/Dark；只请求当前主题资源，避免为选择图片再加主题脚本。网络记录核对初次加载、DPR 2 和 Auto 切换。
4. **完成双主题、响应式和性能验收。**更新素材版本说明及当前设计系统，再保存同条件的改前/改后证据。

接入改动边界：`src/components/HeroArtwork.astro`、`src/views/HomePage.astro`、`src/styles/custom.css`、现有品牌浏览器检查。新素材位于 `public/brand/hero-v2/`；生成母稿、提示词、局部对照和素材验证记录在 `docs/design/brand/hero-artwork/v2/`。实际局部实验输出保存于 `work/hero-experiment/`。

默认 OG、卡片图片生成器和原有素材消费者继续使用其当前交付，本轮不把首页的新主题表现自动传播到所有媒体。访谈中两段 Astro/CSS 示例在读取结果中仅为内容引用占位，因此实施以当前源码及本方案的边界为准。

## 验收条件

- **身份与清晰度：**同一角色、完整满弓和坐骑，无非等比拉伸；在最终尺寸 / DPR 1、2 下检查脸、箭、弓弦及披风局部。两主题体块清楚，Dark 不依靠细白轮廓独自支撑形象。
- **构图：**1440 × 900、1920 × 1080 和 1280 × 800 保留双行标题、清晰说明及首屏主 CTA；图像与文字不相交，容器无裁切、无横向溢出。位置实验记录真实边界和 viewport/DPR。
- **窄屏：**在 320、360、390、768 px 检查单栏顺序、完整图形和回流；390 × 844、360 × 800 无滚动可见完整价值说明及主 CTA，主题/语言控件仍可用。
- **主题与无障碍：**两语言界面、Light/Dark/Auto、系统主题切换；实际选择的图片可解码，布局比例一致；装饰图和星形不重复朗读；焦点、按钮文字/边界对比度及 reduced-motion 行为保持既有要求。
- **媒体与性能：**PNG/WebP 或 SVG 具有正确 MIME，图片响应和 `sizes` 与实际布局相符。Lighthouse 及图片加载/布局检查记录同环境改前/改后结果，目标 LCP < 2.5s、CLS < 0.1；动态响应适用时检查 INP < 200ms，单次实验室评分不证明真实用户 INP。明确记录不可测项，不以源断言代替渲染证据。
- **工程验证：**实施后运行 `npm run check`、`npm test`、`npm run build`、`npm run test:browser`，使用现有生产子路径套件及 full Chromium，保留真实 BFCache/reload 断言。把当前写死的 245 px 素材限制更新为经过审查的新版本/断点规则，不直接删去尺寸断言；图像源分辨率检查也保留。只修改匹配的新素材检查与首页行为，不另建平行内容测试模型。

本轮已完成素材生成、路径描摹、首页接入，以及两语言/双主题的 36 个视口组合、DPR 2 / Auto 选择和首屏几何检查。正式构建、类型检查及单测已通过；生产子路径全套回归仍在核对。上线后可做 5-8 人的短时角色识别与主入口发现对照，作为定性可用性检查，不据此宣称转化率提升。
